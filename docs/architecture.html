Architecture overview

Factory Inventory Management System

A demo full-stack application: a Vue 3 single-page app talks over REST to a FastAPI service that serves in-memory data loaded from JSON files. There is no database and no persistence.

Data flow

  1. User changes a filter FilterBar writes to the four shared refs in useFilters: period, location, category, status. They are module-level singletons, so every view sees the same state.
  2. View reacts and builds the request A watch on the filter refs re-runs the load function. getCurrentFilters() maps period to month and location to warehouse.
  3. API client sends query parameters client/src/api.js drops any filter set to all and calls Axios against http://localhost:8001/api.
  4. FastAPI filters in memory apply_filters handles warehouse, category and status. filter_by_month matches a month directly or expands a quarter such as Q3-2025 through QUARTER_MAP, using the order_date field.
  5. Pydantic validates the response Endpoints declare response_model, so the JSON shape is checked before it leaves the server. The dashboard summary and the spending and report endpoints return plain dicts.
  6. Frontend derives what it shows Raw results sit in refs such as allOrders and inventoryItems. Totals, chart series and rankings are computed properties on top.

Things to know

Gaps found while reading the code

  • api.js calls /tasks and /purchase-orders, but main.py defines no such routes. Both return 404 on the running server.
  • purchase_orders is loaded and used to compute has_purchase_order, but nothing writes to it.
  • Backlog.vue exists but is not registered in the router in main.js.
  • The API base URL is hard-coded to localhost:8001, and CORS allows every origin. Both are suitable for local demos only.
  • Quarter filtering is fixed to 2025 through QUARTER_MAP.
